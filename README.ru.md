# niri-config

*[English version](README.md)*

Самостоятельная конфигурация [niri](https://github.com/YaLTeR/niri), выделенная
из сборки iNiR (Quickshell) и адаптированная под оболочку
[Noctalia](https://noctalia.dev). Зависимостей от iNiR, illogical-impulse и
Quickshell не осталось.

## Установка

На чистой Arch-системе `install/bootstrap.sh` делает всё сам — пакеты, AUR-хелпер,
fish как login shell, greeter, симлинки:

```fish
git clone git@github.com:ivanovichelovek/niri-config.git ~/GitHub/niri-config
cd ~/GitHub/niri-config
sudo ./install/bootstrap.sh
```

Первым делом он спрашивает, для какого пользователя ставить, предлагая того, кто
запустил `sudo`; `--user <имя>` отвечает на это заранее. Дальше каждый шаг просит
подтверждения — см. ниже. Имя важно потому, что конфиг несёт в себе абсолютные
пути с машины, где он писался: `/home/ivanc/...` в биндах,
`dots/noctalia/settings.toml`, `dots/happ/routing.json` и `.desktop`-файлы. Они
переписываются в домашний каталог выбранного пользователя. Это правит
отслеживаемые файлы, поэтому на любой машине, кроме исходной, `git status` потом
покажет их изменёнными — коммитить это обратно не нужно.

Заменяется только путь, голое имя не трогается. `dev.ivanc.RandomWallpaper` —
это application id в обратной нотации DNS, на него завязаны оконное правило в
`90-user-extra.kdl` и имя файла иконки; переименование сломает и то и другое и
ничего не даст.

Вручную:

```fish
git clone git@github.com:ivanovichelovek/niri-config.git ~/GitHub/niri-config
ln -s ~/GitHub/niri-config ~/.config/niri

# вспомогательные скрипты, на которые ссылаются бинды
mkdir -p ~/.local/bin
ln -s ~/GitHub/niri-config/bin/*  ~/.local/bin/
ln -s ~/GitHub/niri-config/dots/fish   ~/.config/fish

# kitty: только файл конфига — themes/ генерирует noctalia
mkdir -p ~/.config/kitty/themes
ln -s ~/GitHub/niri-config/dots/kitty/kitty.conf ~/.config/kitty/kitty.conf
cp    ~/GitHub/niri-config/dots/kitty/theme.conf ~/.config/kitty/themes/noctalia.conf

# telegram: шаблон палитры, который рендерит хук noctalia
mkdir -p ~/.config/noctalia
ln -s ~/GitHub/niri-config/dots/telegram ~/.config/noctalia/telegram

niri validate            # должно напечатать "config is valid"
```

Нужны: `niri`, `noctalia`, `kitty`, `fish`, `zen-browser`, `google-chrome`,
`telegram-desktop`, `yandex-music`, `happ-desktop-bin`, `dolphin`, `cliphist`,
`wl-clipboard` и агент polkit — `bootstrap.sh` ставит всё это сам.

Все вспомогательные скрипты лежат в `bin/` и симлинкуются в `~/.local/bin`:
`lock-and-suspend`, `niri-pin-window`, `niri-toggle-gaps`, `random-wallpaper`,
`noctalia-telegram-theme` и `wlsunset-restart` (его вызывает `lock-and-suspend`).
`claude-state` лежит там же, но запускается руками — см.
[Переезд на новую машину](#переезд-на-новую-машину).

Случайные клики тачпада в nvim лечатся внутри самого nvim (`mouse = ""` в
`~/.config/nvim/lua/config/options.lua`), а не отключением устройства. Более
ранний демон `niri-nvim-touchpad` делал именно последнее через `EVIOCGRAB` и
удалён: ему требовался привилегированный ACL на устройство ввода, и он убивал
тачпад целиком, включая переключение фокуса мышью.

**Каждый шаг спрашивает перед запуском.** Первый вопрос — «отвечать «да» на все
последующие шаги?»: согласиться один раз, и дальше всё пройдёт без вопросов.
Отказ от отдельного шага пропускает его и продолжает работу, причём скрипт
говорит, чего это стоит (без NetworkManager после перезагрузки не будет сети; без
пакетов последующим шагам не с чем работать). Флаг `--yes` задаёт «да на всё»
заранее, а запуск без терминала вообще не спрашивает, вместо того чтобы зависнуть
на `read`.

Флаг `--skip-*` сильнее вопроса: такой шаг даже не предлагается.

Отказ задуман переживаемым, поэтому острые углы сглажены: пропущенный шаг
говорит, чего это стоит, и оставляет строку в итоговом списке «Still to do»;
финальная сводка сообщает, что произошло на самом деле, а не что планировалось;
и ни падение `pacman`, ни отсутствующий systemd-юнит не обрывают установку —
оба предупреждают и продолжают. `networkmanager` есть в `PKGS`, хотя шапка
скрипта причисляет его к предполагаемой базовой системе: `pacstrap base` его не
тянет, и шаг служб потом не мог включить юнит, которого никогда не было.

### Обои

8 изображений (83 МБ) лежат в **отдельном репозитории**
[niri-wallpapers](https://github.com/ivanovichelovek/niri-wallpapers), и шаг
установки клонирует его поверхностно по требованию:

```fish
git clone --depth 1 https://github.com/ivanovichelovek/niri-wallpapers.git
```

Веткой в этом репозитории обойтись было нельзя: **`git clone` забирает все
ветки**, поэтому картинки приехали бы с любым клоном независимо от того, в какой
ветке лежат. Только отдельный репозиторий оставляет клон конфига маленьким.
История `main` при этом была переписана, чтобы выбросить блобы, которые она
раньше несла.

`bootstrap.sh` клонирует во временный каталог, выкидывает `.git` и `README.md`,
копирует через `cp -n` — так повторный запуск никогда не затрёт картинку, которую
вы добавили сами, — и удаляет клон. Если каталог `wallpapers/` уже есть в рабочем
дереве, используется он и ничего не скачивается. Отказ от шага,
`--skip-wallpapers` и отсутствие сети обрабатываются одинаково: настройки
noctalia переводятся на обои, которые она приносит с собой, чтобы оболочке было с
чего стартовать.

`bin/random-wallpaper` **от всего этого не зависит** — он ставится вместе с
остальными вспомогательными скриптами и скачивает картинки сам. Отказ от набора
обоев стоит вам стартовой коллекции, но не приложения.

## Структура файлов

| файл | состояние |
|---|---|
| `10-input-and-cursor.kdl` | без изменений |
| `20-layout-and-overview.kdl` | без изменений (только формулировки комментариев) |
| `30-window-rules.kdl` | правила для приложений + затемнение неактивных (см. [Прозрачность окон](#прозрачность-окон)) |
| `40-environment.kdl` | выброшены venv iNiR и переменные логирования Quickshell |
| `50-startup.kdl` | запускает `noctalia -d` вместо `inir.service` |
| `60-animations.kdl` | без изменений (только формулировки комментариев) |
| `70-binds.kdl` | 37 биндов iNiR переведены на `noctalia msg` |
| `80-layer-rules.kdl` | `quickshell:*Backdrop` → `noctalia-wallpaper` |
| `90-user-extra.kdl` | именованные рабочие столы + привязка приложений + личные бинды |
| `95-pinned.kdl` | **генерируется** `bin/niri-pin-window` — закреплённые окна, грузится последним |

Два файла с автоматизацией приложений — `30-window-rules.kdl` и
`90-user-extra.kdl` — это конфиг компози́тора, и при уходе с iNiR их не пришлось
переделывать вовсе. У Noctalia аналога для них нет и не будет: она
layer-shell-клиент и окнами не управляет.

## Переезд на новую машину

`bin/claude-state save` пакует настройки Claude Code, каталог памяти, стенограммы
сессий и историю запросов — здесь это около 9 МБ против 249 МБ всего `~/.claude`.
`plugins/` и `skills/` не берутся, потому что скачиваются заново, а
`.credentials.json` — потому что живому токену авторизации нечего делать на
флешке; после `claude-state restore` запустите `claude login`.

Восстановление ничего не перезаписывает: существующее состояние сначала
переносится в `.bak.<метка времени>`.

## Random wallpaper

`bin/random-wallpaper` — `Ctrl+Alt+W` или «Random Wallpaper» в лаунчере. Лента
случайных изображений: каждый кадр показывается целиком, вы оставляете его или
выбрасываете, а окно **остаётся открытым и переходит к следующему**. Три кадра
скачиваются на упреждение, так что следующий уже готов.

| клавиша | кнопка | действие |
|---|---|---|
| `S` / `Return` | Save | оставить, дальше |
| `D` / `Backspace` | Delete | удалить загрузку, дальше |
| `→` `←` | `›` `‹` | листать без решения |
| `,` / `F2` | Filters | источник, ориентация, размер, рейтинг |
| `Q` / `Esc` | — | закрыть; всё нерешённое выбрасывается |

Полоса снизу — сама лента, клик по кадру перескакивает на него. Текущий обведён
акцентным цветом.

**Фильтры** сохраняются в `~/.config/random-wallpaper/config.json` (права 0600,
там может лежать API-ключ):

| фильтр | значения |
|---|---|
| Источник | Konachan, Wallhaven |
| Ориентация | Любая, Альбомная, Портретная |
| Минимальный размер | Любой, 1920×1080, 2560×1440, 3840×2160 |
| Рейтинг | Safe, Sketchy, 18+ |
| Категории Wallhaven | General, Anime, People |

У Konachan нет серверного фильтра по размеру, поэтому он забирает 40 кандидатов
со случайной страницы и выбирает подходящий локально. Wallhaven фильтрует на
сервере через `ratios` и `atleast`.

Выше Safe Konachan работает через `konachan.com`. Что отдаст этот хост, зависит от
маршрута: из некоторых сетей он отвечает `302` с
`location: https://konachan.net/`, а `.net` индексирует только безопасные посты,
и поиск возвращается пустым — VPN меняет исход. Запрос делается в любом случае, и
пустой результат сообщает, какой из двух вариантов случился, а не падает молча.

Wallhaven отдаёт Sketchy без аккаунта. Для 18+ нужен API-ключ — впишите его в
фильтрах или задайте `WALLHAVEN_API_KEY` (место для него — гитигнорный
`secrets.fish` у fish). Без ключа API молча выбрасывает nsfw-результаты вместо
ошибки, поэтому приложение проверяет наличие ключа заранее и говорит об этом.

`~/random_wallpaper` захардкожен и создаётся при первом сохранении. **Сохранение
не может уничтожить уже имеющиеся обои**: загрузки лежат в
`~/.cache/random-wallpaper`, пока вы не примете одну из них, а путь сохранения
уникализируется (`-2`, `-3`, …), а не перезаписывается — приложение никогда не
открывает существующий файл на запись. Именно это делал неправильно
`random_konachan_wall.sh` из iNiR: он писал каждую загрузку в один и тот же
`random_wallpaper.jpg`.

Каждое сохранение дополнительно жёстко линкуется в `~/Pictures/Wallpapers` —
именно этот каталог сканируют выбор обоев Noctalia и `wallpaper-random`, а
`~/random_wallpaper` не сканируют. Файловая система та же, так что ссылка не
занимает лишнего места.

Интерфейс — чистый GTK4 со своей таблицей стилей: без libadwaita, и провайдер
регистрируется *выше* `PRIORITY_USER`, чтобы `~/.config/gtk-4.0/gtk.css` не мог
его перекрасить. Иконка:
`share/icons/hicolor/scalable/apps/dev.ivanc.RandomWallpaper.svg`.

Точка osu! с сезонными фонами, которую использовал старый скрипт, теперь отвечает
403 — она ушла за OAuth, поэтому её заменил Wallhaven.

`tests/test-random-wallpaper.py` проверяет свойства неразрушающего сохранения и
логику фильтров на одноразовом `$HOME` — 37 проверок, нужна сеть.

## fish

`dots/fish` — конфиг оболочки; `bootstrap.sh` симлинкует его в `~/.config/fish`.
Нужны `starship` и `eza`, оба ставятся скриптом.

**Секретов в этом репозитории нет.** `config.fish` подключает
`~/.config/fish/conf.d/secrets.fish`, который в `.gitignore` — скопируйте
`dots/fish/conf.d/secrets.fish.example` и заполните. Никогда не кладите ключ в
отслеживаемый файл: удаление его следующим коммитом не удаляет его из истории.

## Neovim

`bootstrap.sh` клонирует [LVim](https://github.com/ivanovichelovek/LVim) (форк
LazyVim) в `~/.config/nvim` по https, затем переводит `origin` на ssh и добавляет
`upstream`, указывающий на LazyVim. Если `~/.config/nvim` уже существует, клон
пропускается. Первый запуск `nvim` ставит плагины и требует сети.

## kitty

Симлинкуется только `kitty.conf`, а не весь каталог: noctalia рендерит
`~/.config/kitty/themes/noctalia.conf` из своего шаблона при каждой смене обоев и
шлёт запущенным экземплярам SIGUSR1, и этому сгенерированному файлу нечего делать
в репозитории. `kitty.conf` подключает его; `theme.conf` здесь — затравка,
копируемая при установке, чтобы у терминала были цвета ещё до первого запуска
noctalia. Включите шаблон kitty в настройках noctalia, чтобы цвета следовали за
обоями.

Строку `include themes/noctalia.conf` держите дословно — `apply.sh` у noctalia
дописывает её, если её нет, а `kitty.conf` является симлинком в этот репозиторий.

`background_opacity 0.85` означает, что сквозь терминал видны обои. Это не
артефакт отрисовки; поднимите до `1.0` для непрозрачного фона.

Отступ задаётся через `window_padding_width`, а **не** `window_margin_width`.
Padding — это «пустая область между текстом и границей окна», она заливается
фоном терминала и потому подчиняется `background_opacity`. Margin — «пустая
область снаружи границы», она не закрашивается вообще: при margin в 21.75pt обои
просвечивали сквозь неё на полную яркость, тогда как область текста сидела за
непрозрачностью 0.85, и жёсткий стык между ними читался как разрез окна посередине.
Ненулевой margin вдобавок заставляет kitty рисовать рамки окна.

`ctrl+f` назначен на киттен `search.py`, которого здесь нет — бинд ничего не
делает, пока вы не положите этот киттен в `~/.config/kitty`.

## Telegram

Telegram Desktop тоже следует за обоями: `bin/noctalia-telegram-theme` собирает
`.tdesktop-theme` из текущей палитры Noctalia и текущих обоев, а запускают его
хуки `colors_changed` и `wallpaper_changed` в `dots/noctalia/settings.toml`.

Это хук, а не шаблон noctalia, потому что тема Telegram — не текстовый файл, а
**zip**, внутри которого `colors.tdesktop-theme` и `background.jpg`, а движок
шаблонов умеет только текст. Сама палитра при этом шаблон —
`dots/telegram/colors.tdesktop-theme`, ~250 цветов в токенах `{{colors.*}}`
noctalia, — и скрипт рендерит его через `noctalia theme -c`, ужимает обои до
1920px и пакует их вместе.

Пишутся две темы из одной палитры, различающиеся одним цветом:

| файл | |
|---|---|
| `~/.config/telegram-desktop/themes/noctalia.tdesktop-theme` | с тонкими разделителями между панелями |
| `~/.config/telegram-desktop/themes/noctalia-flat.tdesktop-theme` | `shadowFg`/`titleShadow` прозрачные — без разделителей |

**У Telegram нет способа перечитать тему снаружи.** Ни IPC, ни CLI; файл
считывается только при старте, и его нужно один раз открыть изнутри Telegram,
чтобы он вообще применился:

> Настройки → Настройки чатов → Темы → ⋯ → Открыть файл темы

После этого хук поддерживает файл в актуальном состоянии, и цвета приезжают со
следующим запуском. `noctalia-telegram-theme --restart` пересобирает тему и
перезапускает Telegram, чтобы применить сразу; сам хук намеренно ничего не
перезапускает, потому что обои крутятся случайной лентой, а убить Telegram
посреди сообщения хуже, чем цвета с отставанием на один запуск.

Палитра рендерится из **светлого** варианта независимо от режима оболочки
(`NOCTALIA_TG_MODE=dark` или `=auto`, чтобы следовать за ним). Тёмные поверхности
Material You почти нейтрально-серые — оттенок обоев в них не виден, и любые обои
дают одинаковые тёмно-серые панели. Оттенок несёт светлая ветка. Учтите: вариант
для рендеринга шаблонов выбирает `--default-mode`, а *не* `--dark`/`--light`,
которые влияют только на вывод JSON.

Вся обвязка — полоса папок, список чатов, верхняя панель, поле ввода, окна, меню —
прибита к `surface_container`, чтобы панели читались как одна поверхность.
`sideBar*` приходится прописывать явно: если оставить их пустыми, Telegram
подставит свои значения по умолчанию, а это чёрная полоса вдоль левого края
светлого в остальном окна.

**Имена палитры зависят от версии, и одно неверное отвергает весь файл.** tdesktop
зашивает палитру по умолчанию в бинарник, поэтому имена можно проверять по
установленной сборке, а не угадывать:

```fish
python3 -c "print(b'outlineButtonBg' in open('/usr/bin/Telegram','rb').read())"
```

`outlineButton*`, `dialogsForward*` и `msgFileOutBgOver` выброшены ровно по этой
причине — они были в старых tdesktop и больше не существуют.

В каталоге сообщества noctalia есть шаблон `telegram`. Он пишет голую палитру в
`~/.config/telegram-desktop/themes/`, без обоев внутри, и здесь не используется.

## Greeter

`--greeter regreet` (по умолчанию) запускает regreet внутри `cage`. **`cage`
завершается, если нет `/usr/bin/Xwayland`**, а `xorg-xwayland` не является ни
жёсткой, ни опциональной зависимостью `cage`, поэтому pacman никогда не поставит
его сам — симптом выглядит как цикл падений с `Cannot create XWayland server` и
следом `Lost connection to Wayland compositor`. `xorg-xwayland` есть в `PKGS`
именно поэтому, а также ради Happ, и шаг с greeter проверяет его повторно.

Как выбраться из циклически падающего greeter: переключитесь на другой VT через
`Ctrl+Alt+F2`, войдите и выполните `sudo systemctl disable --now greetd`. В госте
VirtualBox это сочетание съедает ядро хоста — используйте Host-клавишу (по
умолчанию правый Ctrl), то есть `Right Ctrl`+`F2`. Если переключение VT не
работает вовсе, прервите GRUB, нажмите `e` и допишите
`systemd.unit=multi-user.target` в строку `linux`. Тогда `dots/fish/auto-Niri.fish`
запустит niri при входе на tty1, без всякого greeter.

### В виртуальной машине

Виртуальный GPU не может отдать wlroots буфер для scanout с модификаторами,
поэтому `cage` умирает с `Failed to get buffer handle for plane 0: Invalid
argument`, а greetd перезапускает его по кругу — это другая поломка, нежели
Xwayland выше, но с тем же симптомом. `bootstrap.sh` проверяет
`systemd-detect-virt` и кладёт
`/etc/systemd/system/greetd.service.d/10-virtual-gpu.conf` с
`WLR_RENDERER=pixman`, `WLR_DRM_NO_MODIFIERS=1` и `WLR_NO_HARDWARE_CURSORS=1`.
Программная отрисовка на экране входа ничего не стоит. На реальном железе этот
файл удалите.

`--greeter tuigreet` (только текст) и `--greeter none` обходятся без `cage`
вообще.

## Конфиги приложений

`dots/noctalia/settings.toml` и `dots/happ/{config.json,routing.json}` копируются,
а не симлинкуются — оба приложения переписывают свои файлы сами. Копирование
через `cp -n`, так что переустановка не затрёт изменённые вами настройки.

noctalia держит своё состояние в `~/.local/state/noctalia/`, а не в
`~/.config/noctalia/`, где нет ничего, кроме симлинка `telegram` (шаблон палитры,
см. выше), если вы не добавите собственные переопределения.

Засеянные настройки называют обои абсолютным путём. С `--skip-wallpapers` этот
файл не копировался, поэтому установщик проверяет его и откатывается на
`/usr/share/noctalia/assets/noctalia-wallpaper.png`, который поставляется с
оболочкой. Чтобы эта проверка работала, обои устанавливаются раньше конфигов
приложений.

В `dots/dolphin/` лежат `dolphinrc` и `kservicemenurc`, взятые из iNiR и
копируемые, а не симлинкуемые: Dolphin переписывает `dolphinrc` при каждой смене
режима просмотра и размера окна. Из заметного: `SingleClick=true` (открытие
одним щелчком) и отключённая строка меню (`Ctrl+M` возвращает). Список
миниатюрщиков называет пакеты, которых здесь нет, — отсутствующие Dolphin просто
игнорирует. `darklyrc` и `Kvantum/` тоже взяты из iNiR и теперь
работают: `40-environment.kdl` снова задаёт `QT_QPA_PLATFORMTHEME "kde"` и
`QT_STYLE_OVERRIDE "Darkly"`, за которыми стоят пакеты `plasma-integration`,
`kde-cli-tools`, `kvantum` и `darkly-bin` из AUR. Статичный `kdeglobals` из iNiR
по-прежнему не переносится — эту роль играет шаблон `kcolorscheme` у noctalia,
и он следует за обоями. См. `dots/dolphin/README.md`.

**`subs.db` у Happ в `.gitignore`.** Это база SQLite на 4 МБ с подписками на
серверы — учётные данные, — и ей не место в репозитории. Добавьте подписки заново
из приложения после установки. `config.json` (sing-box: tun, DNS, socks на 10808)
и `routing.json` секретов не содержат, единственные URL в них — публичный DNS и
GitHub.

Больше ничего не переносится. Намеренно выброшены: `btop`, `cava`, `micro`,
`easyeffects`, оформление GTK (`gtk-3.0`, `gtk-4.0`) и `~/.local/share/todoist-remind` с четырьмя его
systemd-юнитами. Поэтому `40-environment.kdl` больше не задаёт
`XDG_MENU_PREFIX`, а
`50-startup.kdl` не запускает `kbuildsycoca6` — всё это требует пакетов, которых
нет.

`Mod+N`, `Mod+Ctrl+N` и `Mod+Ctrl+D` теперь свободны: они управляли
todoist-remind.

## Железо

Список драйверов в `bootstrap.sh` рассчитан на ноутбук с Ryzen 7 5800U:
`amd-ucode` (микрокод *не* входит в `base`), `mesa` + `vulkan-radeon` для
встроенной Vega, `alsa-ucm-conf` для звука. Ethernet (RTL8111), Wi-Fi (RTL8822CE)
и его bluetooth-радио есть в ядре и покрываются `linux-firmware`. GRUB
перегенерируется после установки, чтобы образ микрокода действительно грузился.

`sof-firmware` отсутствует намеренно. На этой машине звук идёт через
`snd_hda_intel`, а к аудиосопроцессору на `04:00.5` не привязан драйвер; установка
прошивки SOF может заставить ядро привязать `snd_sof_amd_renoir` и увести звук на
другой путь. Ставьте её, только если динамики или внутренний микрофон реально не
работают.

47 из 52 пакетов в `PKGS` установлены и работают на целевом ноутбуке сегодня. Пять
оставшихся: `amd-ucode`, `power-profiles-daemon`, `wlr-randr`,
`telegram-desktop` — все они дополняющие — и `sof-firmware`, ныне удалённый.

На другом железе правьте блок в начале `PKGS`: `vulkan-intel` для Intel,
`nvidia-open-dkms` + `egl-wayland` для NVIDIA.

## Прозрачность окон

Неактивные окна затемняются до `0.8` (`match is-active=false` в
`30-window-rules.kdl`), чтобы активное читалось с одного взгляда. Две категории
исключены, и оба правила стоят **ниже** правила затемнения — правила применяются
сверху вниз, и побеждает последнее совпадение:

| правило | зачем |
|---|---|
| `is-floating=true` | плавающие окна — намеренные, короткоживущие накладки |
| `app-id="scrcpy"` | зеркало телефона существует, чтобы смотреть в него *во время* работы в другом окне |

Режим фокуса (`Mod+Shift+F`, `bin/niri-toggle-gaps`) на время своей работы
отключает затемнение. Он глушит правило целиком узловым префиксом `/-` KDL, а не
переписывает число: в файле теперь несколько строк `opacity`, и прежний `sed` по
значению переписал бы вместе с ним и исключения выше.

Отдельно: kitty полупрозрачен сам по себе (`background_opacity 0.85`, см.
[kitty](#kitty)). Поэтому сквозь терминал видны обои даже при полной
непрозрачности со стороны компози́тора — это kitty, а не затемнение, и niri этого
не отменяет. Только собственная настройка kitty.

### Закрепление окна — `Mod+O`

`bin/niri-pin-window` переключает закрепление на текущем окне: закреплённые окна
сохраняют полную непрозрачность, когда фокус уходит. Скрипт пишет настоящее
`window-rule` в генерируемый `config.d/95-pinned.kdl`, который niri подхватывает
при записи.

```fish
niri-pin-window            # переключить текущее окно (это и делает Mod+O)
niri-pin-window --list     # что закреплено
niri-pin-window --clear    # снять все закрепления
```

Каждое нажатие шлёт уведомление, так что результат виден и не нужно выискивать
разницу в 20% прозрачности.

**Почему скрипт, а не штатное `toggle-window-rule-opacity`.** Это действие не
переживает смену фокуса, если применить его к *сфокусированному* окну: niri
пересчитывает оконные правила при каждом изменении `is-active`, и пометка на окне
теряется — ровно тогда, когда должна была начать работать. К уже неактивному окну
(`--id`) оно применяется и держится, но у хоткея нет другого окна, к которому он
мог бы обратиться. Проверено на niri 26.04 скриншотами обоих путей.

`is-urgent=true` выглядит подходящим маркером для той же задачи и им не является:
niri сбрасывает «срочность» в момент фокусировки окна.

**У бинда стоит `allow-inhibiting=false`**, без которого он никогда не сработал бы
на окнах, которые закреплять важнее всего. `allow-inhibiting` по умолчанию `true`,
и любой клиент, удерживающий протокол keyboard-shortcuts-inhibitor, съедает такие
бинды — scrcpy делает именно это, чтобы пересылать сочетания на телефон.
`Mod+Escape` (`toggle-keyboard-shortcuts-inhibit`) — глобальный аварийный выход, и
у него то же свойство по той же причине.

**Ограничение:** оконные правила не умеют адресовать окно по id, поэтому
закрепление совпадает по `app-id` + **точному заголовку**. Если окно потом сменит
заголовок — терминалы делают это на каждый каталог, браузеры на каждую вкладку —
правило перестанет совпадать, и закрепление молча отвалится. Нажмите `Mod+O` ещё
раз или сбросьте всё через `--clear`.

`95-pinned.kdl` отслеживается git, но закоммичен пустым, чтобы `include`
разрешался на свежем клоне ещё до первого запуска скрипта. Закрепления после
этого будут видны в `git status`.

`hotkey-overlay-title` у бинда — это то, что помещает его в шпаргалку `Mod+/`:
оверлей называется «Important Hotkeys» и иначе показывает только захардкоженный в
niri набор — `Mod+F`, `Mod+C` и бинды изменения размера в нём тоже отсутствуют.

## Бинды оболочки

Noctalia не может перехватывать глобальные клавиши — она layer-shell-клиент,
поэтому все сочетания принадлежат компози́тору и передаются ей по IPC. Назначайте
клавиши здесь; список команд — `noctalia msg --help`.

| клавиша | действие |
|---|---|
| `Mod+Space` | лаунчер приложений |
| `Mod+V` | панель буфера обмена |
| `Mod+Shift+C` | центр управления *(новое)* |
| `Mod+Comma` | настройки оболочки |
| `Mod+Shift+Q` | сессия / питание |
| `Ctrl+Alt+T` | выбор обоев |
| `Mod+Shift+S` | скриншот области |
| `Mod+Ctrl+S` | скриншот всего экрана *(новое)* |
| `Mod+Alt+L` | блокировка |
| `Mod+Alt+Shift+L` | блокировка, затем сон (`bin/lock-and-suspend`) |
| `Mod+Slash` | шпаргалка по хоткеям niri *(была своя у iNiR)* |
| `Alt+Tab` | переключатель окон |
| `Ctrl+Alt+W` | просмотрщик случайных обоев *(новое)* |
| `Mod+Shift+F` | режим фокуса — без отступов, скруглений, затемнения и панели |
| `Mod+O` | закрепить окно на полной непрозрачности *(новое)* |
| `Mod+Escape` | вернуть бинды, перехваченные приложением |

Громкость, яркость и медиаклавиши идут через `noctalia msg` ради экранной
индикации.

У каждого из них задан `hotkey-overlay-title`, поэтому `Mod+/` называет действие,
а не выводит десяток одинаковых строк «Spawn noctalia». Два следствия, о которых
стоит помнить при правке: аппаратные клавиши `XF86*` выставлены в
`hotkey-overlay-title=null` и в список не попадают — они подписаны на самой
клавиатуре, — а niri **схлопывает строки с одинаковым заголовком**, поэтому
дублирующие медиа-бинды (`Mod+Shift+P`/`N`/`B`, те же действия, что у
`Ctrl+Mod+Space` и `Mod+Alt+N`/`P`) скрыты явно, вместо того чтобы молча съесть
строки выше.

## Выброшено — нет аналога в Noctalia

Оставлено закомментированным на месте в `70-binds.kdl`:

- `Alt+Shift+Tab` — у `window-switcher` нет обратного направления
- `Mod+Shift+X` — OCR области (см. AUR `noctalia-plugin-screenshot-ocr`)
- `Mod+Shift+A` — поиск области через Google Lens
- `Mod+Shift+R` — запись экрана со звуком (при желании привяжите `wf-recorder`)
- `Super+G` — оверлей-перекрестие
- `Mod+Shift+W` — переключение семейств панелей iNiR

`Mod+Q` теперь использует родной `close-window` у niri; iNiR оборачивал его в
диалог подтверждения для несохранённой работы, которого у Noctalia нет.
